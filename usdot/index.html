A shared “where” for the Digital Corridors — demonstrated, and ready to hand over

What was built, what it proved, and how USDOT can carry it past the states — to the OEMs, ADAS platforms, freight carriers, and local agencies who would subscribe to these feeds the same way this demonstration already does. Everything here is open, reproducible, and running today.

1What was demonstrated

  • A national reference network that already exists. Every signed US interstate — 77,220 Overture segments with stable GERS identifiers — serves as the shared vocabulary. Free, versioned monthly, published on open infrastructure, on a standardization path with OGC.
  • Live multi-state conflation, with no infrastructure at all. A public web page fetches state DOTs’ existing 511/WZDx feeds and joins them to GERS identifiers in the viewer’s browser: in a Nov 23, 2026 snapshot, 10,534 live events from 24 states, 2,931 matched at 2.0 m median snap, with method and distance recorded on every join. Feeds whose hosts block browser access ride a thin allowlisted relay — the same pattern USDOT could run once, nationally. Multiple feed schemas, including one with no structured location field at all, read as one keyed dataset. See it live.
  • The national inventory, measured. Every feed in USDOT’s Work Zone Data Feed Registry was probed (a public page re-runs the test from any browser): 35 states publish; 14 feeds sit behind API keys; the rest are one reachability header away from joining. Notably, four live statewide feeds (GA, NE, UT, NM) were found outside the registry — actual availability exceeds the official count.
  • The replication kit. An open-source tagger (feed in → GERS-referenced feed out, with a match report), a one-day adoption playbook per state, and this entire demonstration as a public repository.

The sentence this earns

Cross-state conflation is no longer the hard part of Digital Corridors — a browser does it on page load. The remaining work is adoption: an optional location_references field in CWZ/WZDx, keys or a thin relay for the gated feeds, and a seat for the subscribers below.

2Who subscribes next — the same way this page does

The demonstration consumes public feeds exactly as any third party would: fetch, join on the segment ID, done. Every group below can subscribe today with the same three steps — and several can also publish back on the same key.

OEMs & ADAS platforms

Consume work zones keyed to segments for in-vehicle alerts — one integration valid in every participating state, instead of per-state agreements. Publish back aggregated observations (work-zone confirmations, hard-braking clusters, road damage) on the same IDs: the Waymo–Waze pothole precedent, made portable and vendor-neutral.

Navigation & freight platforms

Pre-trip truck routing around construction across jurisdictions; consume authoritative truck-route and restriction layers on the same key as they come online. A 2,000-mile load planned the way airlines plan around weather.

Cities & counties

Subscribe to the segments feeding their street grids: a freeway closure triggers signal retiming plans and officer dispatch for the detour load, with the emergency-services incident ID carried beside the segment ID for cost recovery.

Corridor coalitions & TMCs

One corridor picture across member states without bilateral integration; event-driven coordination (construction holds, debris surges) instead of phone trees.

Insurers, researchers, analysts

Segment-keyed event and exposure histories — crash context, work-zone exposure, disruption frequency — joinable to any other segment-keyed dataset without conflation projects.

FHWA / BTS

The national needs ledger: usage, risk, condition, and disruption on one segment vocabulary, so “which roads cost the nation the most” becomes a query over open data.

3What USDOT could do with this on Monday

  1. Accept the reference where it costs nothing: an optional, additive location_references entry (segment ID + reference-dataset release) in the CWZ/WZDx spec — precedent exists, since WZDx already carries parallel location descriptions.
  2. Measure coverage in the registry: add columns for browser reachability (CORS) and shared-reference coverage — the feed tester shows the data is one probe away — and fold in the live statewide feeds currently missing from it.
  3. Point GADC applicants at the kit: the playbook makes “publish a GERS-referenced feed” a one-line, verifiable work item in any corridor data plan.
  4. Stand up the thin relay once, for the key-gated feeds: one small shared service holding the 14 API keys and re-publishing those feeds with references attached — the only new infrastructure this entire picture requires.
  5. Convene the subscribers: the OEM and ADAS companies already coordinate in AVSC; nav and freight platforms already consume WZDx. The ask to each is one pilot, one corridor, one observation class.
